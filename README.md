# Agent Workspace

Переносимые проекты и краткое состояние задач для Codex. MCP-сервер хранит записи и готовые результаты в обычной синхронизируемой папке. Synology Drive, Google Drive или другой файловый клиент доставляет её между ПК.

Исходники проектов остаются локально. Агент сохраняет цель, этапы, решения, уверенность и основания, проверки, незавершённые вопросы и следующий шаг. Полный чат по умолчанию не переносится.

## Установка готового комплекта

1. Установите Codex и клиент синхронизации. Дождитесь загрузки существующей общей базы `AI-Workspace` с файлом `workspace.json`.
2. Полностью распакуйте готовый `Agent-Workspace-Setup.zip` из Releases в локальную папку.
3. Прочитайте `0_Описание.rtf`.
4. Приложите `1_Установка_агента.md` в чат Codex и напишите: «Установи правила агента по приложенной инструкции».
5. Приложите `2_Установка_MCP.md` и напишите: «Установи MCP Agent Workspace по приложенной инструкции».
6. В появившемся окне выберите существующую `AI-Workspace`. Агент сам проверит и распакует программу, настроит подключение и сохранит резервные копии. После обоих шагов один раз перезапустите Codex и проверьте MCP.

Первый файл добавляет инструкции уже установленному Codex. Приложение Codex в комплект не входит. Готовый Windows x64 runtime Node.js включён в пакет MCP.

## Использование

- **«Начни работу»** — проверить доставленные версии, загрузить принятую запись задачи и выбранные готовые файлы.
- **«Закончи работу»** — сохранить краткий handoff, фактический статус, основания решений, проверки и готовые результаты.
- При расхождениях агент показывает сравнение и рекомендацию; основную версию выбирает пользователь.

Окончание сессии не означает завершение всей задачи. Успешная запись в локальную папку не подтверждает доставку на NAS или другой ПК. Таймера и автоматического перехвата закрытия окна нет.

## Данные и архитектура

- `src/store.js` — история ревизий, контрольные суммы, сравнение, выбор версии, готовые объекты и восстановление.
- `src/server.js` — 10 MCP-инструментов через stdio.
- `src/schema.js` — структура и проверки handoff.
- `src/codex.js`, `src/vault.js` — переносимые описания настроек, локальные привязки и отдельный шифрованный vault.
- `native/FolderPicker.cs` — стандартное окно выбора папки Windows.
- `packaging/simple/` — переносимые инструкции установки и описание комплекта.

## Разработка

Для ядра нужны Node.js 22+ и pnpm. Версии зависимостей зафиксированы в `pnpm-lock.yaml`.

```text
pnpm install --frozen-lockfile
node scripts/check.js --suite core
node scripts/check.js --suite protocol
node scripts/check.js --suite credentials
```

Проверки используют синтетические данные в `work/`, оставляют наблюдения для осмотра и не удаляют каталоги рекурсивно. Они не изменяют реальные настройки Codex или общую пользовательскую базу. Готовые `node.exe`/ZIP и рабочие данные не хранятся в Git.

## Сборка Windows x64

Сборка выполняется на Windows x64. Нужны Node.js 22+, pnpm и штатный C# compiler .NET Framework 4.x по пути `%SystemRoot%/Microsoft.NET/Framework64/v4.0.30319/csc.exe`. Для простого установочного комплекта дополнительно нужен Python 3.10+; внешние Python-пакеты не используются.

```text
pnpm build
node scripts/verify-release.js
python scripts/build-kit.py
```

Результаты создаются в `output/`: отдельный готовый runtime, его ZIP, простой комплект `Agent-Workspace-Setup/` и общий ZIP с SHA-256. Каталоги и архивы сборки не перезаписываются молча. Для повторного выпуска используйте чистое место сборки или сохраните прежние результаты отдельно.

При необходимости отдельно выполните `scripts/smoke-release.ps1` через PowerShell 7. Это запуск готового CLI/stdio на синтетических данных, а не проверка другого физического ПК. Сборка не подтверждает работоспособность реальной облачной доставки.

## Локальная командная строка

Для исходников: `node src/app.js help`. Для готового пакета: `agent-workspace.cmd help`.

Основные команды: `init`, `attach`, `startup`, `project`, `get`, `save-task`, `review`, `choose`, `result`, `package`, `restore`, `serve`. Команда `init` создаёт новую пустую базу, `attach` подключает существующую. Для исходного CLI путь можно передать через `--root`; графический helper поставляется с готовым Windows-пакетом.

## Ограничения

MCP не является облачным синхронизатором и не содержит собственной модели ИИ. Сводку формирует агент. Авторизация приложений, OAuth-кеши и рабочие БД не клонируются. Переносимые статические секреты можно сохранять отдельно в зашифрованном vault; пароль не хранится рядом и не передаётся через чат или аргументы команды.

Контрольные суммы показывают целостность, а не автора. Проверки путей уменьшают риск перенаправления через symlink/junction, но не являются транзакционной защитой от активной подмены другим процессом. Полный цикл на втором физическом ПК проверяется отдельно.
