# Перенос готовых файлов и ссылок

Начиная с ReHome 0.1.41-beta.1, выбранные готовые файлы включаются в копию вместе с привязкой к ссылкам в сообщениях ассистента. При восстановлении ReHome создаёт новые папки проектов и заменяет адреса связанных ссылок на пути к восстановленным файлам.

## Дополнить существующую копию

Выполняйте эти шаги на исходном ПК, где доступны готовые файлы. Codex для дополнения готовой копии закрывать не требуется: операция не изменяет рабочий профиль.

1. Откройте ReHome и при необходимости выберите папку хранения новых копий.
2. Нажмите **«Найти файлы по ссылкам в копии»** и выберите отдельную папку существующего бекапа, внутри которой находятся `manifest.json`, `ReHome.json` и `Chats`.
3. Просмотрите список. Выделите только готовые результаты, которые хотите перенести. Кнопка **«Выделить доступные»** помогает выделить доступные файлы; проверьте состав перед добавлением. Ссылка в чате сама по себе не доказывает, что файл является готовым результатом.
4. Если файл перемещён или ссылка относится к старому sandbox-пути, выделите одну строку, нажмите **«Указать локальный файл»** и выберите соответствующий готовый файл. Не сопоставляйте разные результаты только по совпадению имени.
5. Нажмите **«Добавить выбранные»**, затем **«Создать копию с выбранными файлами»**. Дождитесь сообщения с путём новой проверенной копии. Исходный бекап сохраняется отдельно.
6. Перед переносом на другой ПК дождитесь синхронизации всей новой папки. Восстанавливайте именно новую копию, содержащую файлы.

Если исходный бекап изменился после просмотра списка, операция остановится. Повторите поиск и проверьте выбор заново. Отсутствующие файлы ReHome не воссоздаёт из текста или имени ссылки; их нужно найти на исходном ПК или скачать из исходного сервиса.

Кнопка **«Очистить список»** сбрасывает выбор файлов в текущем окне, не удаляя их с диска. Для ранних копий формата 1, уже содержащих результаты без сведений об исходных путях, создайте новый бекап и заново выберите результаты. Ранние копии без готовых файлов можно дополнить описанным выше способом.

## Создать новую копию

Можно по-прежнему нажать **«Выбрать готовые файлы»**, указать результаты и их проекты, затем **«Создать бекап»**. Если выбранный файл точно соответствует локальной ссылке в сообщении ассистента этого проекта, ReHome сохранит её привязку. Для связи с другим старым путём используйте просмотр ссылок в уже созданной копии и явное указание локального файла.

## Где находятся файлы

В копии: `Projects/<ID проекта>/Results/<идентификатор файла>/<имя файла>`.

После восстановления по умолчанию: `C:\Users\<пользователь>\Documents\ReHome\Projects\<папка проекта>\Results\<идентификатор файла>\<имя файла>`.

Одинаковые имена из разных исходных папок не перезаписывают друг друга. При повторном восстановлении создаётся новая папка проекта; ссылки указывают на файлы этого восстановления. Чаты без проекта используют отдельную папку «Без проекта».

## Какие ссылки поддержаны

- Встроенные Markdown-ссылки вида `[отчёт](C:/путь/отчёт.pdf)` и назначения в угловых скобках, включая пробелы и кириллицу.
- Абсолютные Windows-пути, локальные `file:///` URI, абсолютные POSIX/sandbox-пути при явном сопоставлении с доступным локальным файлом.
- Повторные ссылки на один выбранный файл в том же проекте, в обычных и архивных чатах.

Относительные пути и ссылочные определения Markdown вида `[отчёт][id]` автоматически не сопоставляются. Веб-ссылки, обычный текст путей, примеры внутри блоков кода и сообщения пользователя не изменяются. Не включённые в копию файлы не получают новых адресов.

Исходный текст истории остаётся в `Chats/transfer.json` внутри бекапа. В восстановленной рабочей истории меняются только адреса подтверждённых ссылок. Перечень замен `Relocations.json` хранится в служебном каталоге подготовки операции на целевом ПК; проверка сверяет его с оригиналом и файлами копии. Метки архива, идентификаторы сообщений, даты и остальной текст сохраняются. Откат возвращает прежнюю историю вместе с прежними папками проектов.

## Архивация чатов Codex

Штатный `thread/archive` перемещает журнал чата в каталог архивных сессий; `thread/unarchive` возвращает его в активные. Архивные чаты запрашиваются отдельно с `archived: true`. Это полезно для организации завершённых работ, но не упаковывает готовые файлы и не меняет пути ссылок. ReHome включает обычные и архивные чаты и сохраняет их статус. Архивировать чаты перед переносом не требуется.

Источник: [официальная документация OpenAI — Archive a thread](https://learn.chatgpt.com/docs/app-server#archive-a-thread). Не следует считать архивацию резервным копированием или обещанием уменьшения занятого места.
