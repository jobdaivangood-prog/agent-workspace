# Проверка повторов и оптимизация 0.3.0

Проверка выполнена 29 октября 2026 года. Оптимизация нужна: прежняя версия сохраняла только одну задачу и могла создавать новую ревизию при повторе того же handoff. В 0.3.0 обход всех доступных локальных чатов отделён от подготовки сводок и сохранения.

| Участок | Избыточная работа или риск | Изменение |
| --- | --- | --- |
| История неизменённого чата | Полное повторное чтение | Один последний шаг: ID, SHA-256 публичных сообщений, статус шага и метаданные |
| Изменённый чат | Повторное чтение старой части | Чтение до сохранённой опоры; полный аудит только при необходимости |
| Каталог базы | Startup и второй такой же scan | Один проверенный проход, внутренний chat_index |
| Страницы списка | Повторное перечисление и пересортировка | Замороженный список и исходные ревизии в локальном run_id |
| Одинаковый handoff | Новая ревизия без изменения данных | Нормализованное сравнение после проверок базы; прежняя ревизия |
| Повтор после сбоя | Повторная запись уже сохранённой задачи | Локальная квитанция с digest и ревизией; продолжение незавершённой операции |
| Готовый объект у нескольких записей | Повторное хеширование одного ZIP | Один digest в пределах операции; каждый раз проверяются путь, тип, размер и идентичность файла |
| Startup без новых версий | Перезапись selected.json | Неизменившаяся карта выбора не перезаписывается |
| Работающий чат | Чтение промежуточного состояния | Известные активные чаты пропускаются до чтения; текущий чат имеет явную границу снимка |

Сводки готовит агент только для изменённых чатов. Проверка списка и контрольных сумм выполняется локальным кодом без обращения к модели. Общая экономия токенов зависит от числа изменённых чатов; процент экономии не измерялся.

Нельзя считать полным ограниченный фрагмент истории, молча менять expected_revision или создавать другую задачу в обход неполной доставки. Неполное чтение возвращает pending_history; переписанная история после полного аудита требует одобрения показанной новой сводки. Новые исходники, переписки, пароли и произвольно найденные файлы в общую базу не публикуются.

У протокола Codex нет единого надёжного номера ревизии всей истории. Проверка последней опоры не гарантирует обнаружения ранней правки до неё; для этого предусмотрен fullAudit. Номер строки, размер файла и дата изменения такой гарантии также не дают.

Один локальный writer.lock защищает от одновременных локальных записей. Передача сторонним облачным клиентом не является транзакцией. Подтверждённая локальная запись не доказывает доставку на NAS и другие ПК. Если процесс прервался до записи квитанции, нужен новый scan с проверкой базы.

Повторный обход может создавать служебные локальные файлы и кратковременный lock; требование «не перезаписывать без изменений» относится прежде всего к сводкам, курсорам и файлам общей базы. Таймер, дополнительная модель, фоновая служба и постоянный наблюдатель для этого не требуются.

Официальный интерфейс истории: [Codex App Server](https://learn.chatgpt.com/docs/app-server). Конкретные результаты проверок приведены в [VALIDATION.md](VALIDATION.md).
