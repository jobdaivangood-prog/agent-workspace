# Проверка проекта

Наличие исходников, документации или собранного пакета не подтверждает успешный запуск. При выпуске фиксируйте результаты отдельно и указывайте реальную область проверки.

## Синтетические проверки

```text
node scripts/check.js --suite core
node scripts/check.js --suite protocol
node scripts/check.js --suite credentials
```

Core проверяет начальное состояние, выбор пользователя, параллельные ветви, неполную доставку, контрольные суммы, восстановление результатов, смену папки и ограничения путей/схемы. Protocol использует официальный клиент и InMemoryTransport в одном процессе. Credentials использует только искусственные настройки, непрозрачные значения и пароли.

## Проверка сохранения всех чатов в 0.3.0

В проверяемые сценарии входят:

- Постраничное перечисление обычных и архивных чатов, исключение служебных дочерних чатов, явный отчёт о недоступных источниках.
- Повторная проверка читает хвост; неизменившиеся ID и отпечаток не вызывают полного чтения, подготовки сводки и новой записи.
- Новый шаг загружается как прирост; изменение или исчезновение сохранённой границы не выдаётся за обычное добавление.
- Страницы одного run_id обходят зафиксированный перечень без пропусков; новые чаты после снимка относятся к следующему запуску. Известные активные чаты передаются из приложения отдельно от статусов процесса чтения.
- Усечённое чтение возвращает pending_history и не продвигает указатель. Восстановление после изменения/исчезновения границы требует полного аудита и явного одобрения показанных изменений/сводки; без него needs_history_review не может быть сохранён как обычный прирост.
- Изменение заголовка сохраняет связь с прежней задачей. Работающий чат не получает ложный статус completed или closed.
- Снимок не содержит reasoning, вывод инструментов или скрытые элементы истории. Сводка с ограниченной областью чтения явно отмечает её.
- Сохранение использует базовую ревизию снимка; изменение базы после проверки отклоняется. Конфликт и неполная доставка не обходятся через unchanged.
- Идентичный handoff с теми же артефактами возвращает прежнюю ревизию; число каталогов ревизий, байты и время изменения её файлов остаются прежними.
- Задача и служебный указатель прочитаны после сохранения; сбой одного чата отражается в отчёте и не выдаётся за успешное сохранение всех.
- Чаты и пользовательские снимки не попадают в исходники, тестовые fixtures, ZIP готовой программы или GitHub.

29 октября 2026 года на Windows x64 с Node.js 24.22.1 выполнен полный `node scripts/check.js`: **51 passed, 0 failed** (ядро 19, протокол 1, переносимые настройки 6, источник чатов 13, синхронизация чатов 12). Проверены неизменные данные и файлы, одна последняя запись вместо всей истории, замороженный список, отсутствие дубликата при неполной доставке, восстановление после частичной ошибки, исходные ревизии и обязательный выбор при переписанной истории. Тесты используют синтетические данные; модель, реальная общая база и реальные чаты ими не изменяются.

Отдельное чтение настоящего Codex App Server 0.162.1 подтвердило постраничный список обычных/архивных чатов и повторную проверку неизменённого чата за один последний шаг. Тексты из этой проверки не публиковались. Массовое составление и сохранение сводок всех реальных чатов этой проверкой не выполнялось.

Ограничение хвостовой проверки остаётся даже при прохождении тестов: она не доказывает отсутствие раннего редактирования до неизменившейся границы.

Данные остаются в work для осмотра. Автоматического удаления тестовых каталогов и вложенного запуска Node-тестов нет. Проверки должны выполняться с доступом к разрешённой локальной тестовой папке; ошибка прав на предков пути не является основанием убирать проверки канонических путей.

## Проверки 0.3.1

На Windows x64 выполнен полный `node scripts/check.js`: **64 passed, 0 failed**, включая 13 проверок локального читателя. После исправления обработки текущего изменяющегося шага отдельно повторён набор источника чатов: **14 passed, 0 failed**, в том числе один новый сценарий. Всего подтверждены 65 различных проверок в этих запусках; это не один полный запуск 65 тестов.

Проверки читателя используют синтетические файлы и не запускают дочерний Codex или модель. Покрыты стабильный launcher/junction, повторное разрешение после смены цели, настроенный путь в приоритете, ограниченное локальное обнаружение, объединение совпадающих физических файлов, отсутствие и неоднозначность установки. Запрет symlink/junction для общей базы, local storage и пакетов сохранён.

Дополнительный сценарий отличает нормальный переход текущего шага inProgress → completed от изменения ранее завершённой истории: первый не требует согласования переписанной истории, второе по-прежнему требует проверки. Эти синтетические результаты не подтверждают доставку NAS или работу второго физического ПК.

## Готовый выпуск

1. `pnpm build` собирает отдельный runtime для Windows x64.
2. `node scripts/verify-release.js` проверяет структуру и контрольные суммы, но не запускает программу.
3. При необходимости запустите `scripts/smoke-release.ps1` через PowerShell 7: реальный готовый CLI и stdio, искусственные две копии базы и готовый результат. Конфигурация пользователя не используется.
4. `python scripts/build-kit.py` создаёт ZIP runtime и простой комплект, сверяя содержимое архивов.
5. Окно FolderPicker, отмена и действительный выбор папки человеком проверяются отдельно. Проверка не должна отключать антивирус, менять его исключения или политику PowerShell.

Протокольная проверка stdio не доказывает появление инструментов в уже открытом чате. После перезапуска клиента отдельно проверьте workspace_startup и чтение принятой задачи из нового каталога инструментов.

## Реальные несколько ПК

Физическая доставка Synology/другим провайдером, продолжение на втором ПК и ручной выбор при расхождении требуют отдельного сценария. Локальная копия каталога в тесте не считается проверкой NAS или второго физического ПК.

При инциденте защиты сохраните исходное событие и диагностические данные локально. Не объявляйте его ложным срабатыванием без подтверждения. Пользовательские журналы, пути, переписки и конфигурации не включайте в публикуемые исходники или готовые пакеты.
