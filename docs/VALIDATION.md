# Проверка проекта

Наличие исходников, документации или собранного пакета не подтверждает успешный запуск. При выпуске фиксируйте результаты отдельно и указывайте реальную область проверки.

## Синтетические проверки

```text
node scripts/check.js --suite core
node scripts/check.js --suite protocol
node scripts/check.js --suite credentials
```

Core проверяет начальное состояние, выбор пользователя, параллельные ветви, неполную доставку, контрольные суммы, восстановление результатов, смену папки и ограничения путей/схемы. Protocol использует официальный клиент и InMemoryTransport в одном процессе. Credentials использует только искусственные настройки, непрозрачные значения и пароли.

Данные остаются в work для осмотра. Автоматического удаления тестовых каталогов и вложенного запуска Node-тестов нет. Проверки должны выполняться с доступом к разрешённой локальной тестовой папке; ошибка прав на предков пути не является основанием убирать проверки канонических путей.

## Готовый выпуск

1. `pnpm build` собирает отдельный runtime для Windows x64.
2. `node scripts/verify-release.js` проверяет структуру и контрольные суммы, но не запускает программу.
3. При необходимости запустите `scripts/smoke-release.ps1` через PowerShell 7: реальный готовый CLI и stdio, искусственные две копии базы и готовый результат. Конфигурация пользователя не используется.
4. `python scripts/build-kit.py` создаёт ZIP runtime и простой комплект, сверяя содержимое архивов.
5. Окно FolderPicker, отмена и действительный выбор папки человеком проверяются отдельно. Проверка не должна отключать антивирус, менять его исключения или политику PowerShell.

Протокольная проверка stdio не доказывает появление инструментов в уже открытом чате. После перезапуска клиента отдельно проверьте workspace_startup и чтение принятой задачи из нового каталога инструментов.

## Реальные несколько ПК

Физическая доставка Synology/другим провайдером, продолжение на втором ПК и ручной выбор при расхождении требуют отдельного сценария. Локальная копия каталога в тесте не считается проверкой NAS или второго физического ПК.

При инциденте защиты сохраните исходное событие и диагностические данные локально. Не объявляйте его ложным срабатыванием без подтверждения. Пользовательские журналы, пути, переписки и конфигурации не включайте в публикуемые исходники или готовые пакеты.

Текстовые исходники и вложенные архивы проверены на отсутствие локальных путей, идентификаторов рабочей базы и пользовательских конфигураций. Эти результаты относятся к конкретной локальной публикационной сборке; повторная сборка требует своей проверки. Реальная доставка на NAS, второй физический ПК и обновление инструментов в уже открытом чате этим не подтверждаются.
