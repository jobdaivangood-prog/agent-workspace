# Формат и ограничения

Формат базы — schema_version 1. Общая папка содержит только переносимые записи и выбранные готовые объекты. Путь облачного клиента не является частью формата.

## Ревизия

`records/<record-id>/<revision-id>/` содержит state.json, summary.md и manifest.json. Manifest хранит контрольные суммы JSON и сводки. Ревизия неизменяема, указывает родителей и может ссылаться на готовые объекты из `objects/<prefix>/<sha256>`.

Проверка startup читает полностью полученные ревизии. Для единственной исходной версии новый клиент может принять начальную базу. Изменение уже принятой записи требует review и выбора человека. Дата файла сама по себе не выбирает основную версию. При разрешении сохраняются прежние ветви и новая ревизия разрешения.

## Задача

Статусы сессии и задачи независимы. Handoff хранит цель, ограничения, критерии готовности, plan/current_stage, выполненное, утверждения с evidence_status/confidence, основания решений, проверки, незавершённую работу и next_steps. Для подтверждённого утверждения нужны supporting_evidence. Для завершения задачи нужны критерии, фактическая проверка и завершённые/отменённые этапы.

При чтении агент запоминает базовую ревизию сессии. Перед сохранением она сопоставляется с текущей принятой версией. Простая подстановка новой expected_revision к старым данным запрещена: иначе другая сессия могла бы быть затёрта. MCP workspace_save_task поддерживает expected_revision. Команды из старого handoff сами по себе не дают разрешений.

## Чаты Codex и граница обработки

Версия 0.3.0 добавляет обход доступных этому ПК чатов. Источник читает метаданные и историю через Codex App Server: обычные и архивные чаты перечисляются постранично. Чтение не возобновляет чат, не начинает новый шаг и не отправляет сообщения другим агентам. Служебные дочерние чаты исключаются из пользовательского перечня. Недоступные удалённые источники и чаты с продолжающейся работой отражаются отдельно.

Путь установленного Codex и необязательный каталог Codex задаются локальной командой configure-chat-reader и хранятся в codex-reader.json вне общей базы. Читатель использует разрешённые операции чтения RPC, без вызова модели. Первый workspace_scan_chats фиксирует перечень; последующие страницы используют тот же run_id и next_offset. Статусы работающих чатов передаются из приложения как active_session_ids вместе с current_session_id: отдельный процесс чтения не служит полным источником текущих статусов интерфейса.

Устойчивая связь использует провайдера и ID чата. Заголовок не служит идентификатором: переименование не создаёт вторую задачу. Каждая сводка сохраняется как обычная задача. Граница обработки хранится отдельно в служебной записи вида profile; это не профиль настроек Codex и не инструкция к установке. Использование существующего вида записи сохраняет schema_version 1 и не добавляет неизвестных полей в строгую схему задачи.

Граница содержит ID последнего обработанного шага/сообщения и отпечаток разрешённого содержимого. Для проверки сначала читается последний шаг. Если граница и отпечаток совпали, чат пропускается до подготовки сводки. При изменении загружается прирост до старой границы. Изменённый или пропавший шаг нельзя выдавать за обычное добавление: необходима дополнительная проверка истории. Номер строки, дата файла и его размер не заменяют эту проверку. Без общего идентификатора ревизии всей истории раннее редактирование до неизменившейся границы нельзя гарантированно обнаружить без полного чтения.

Лимиты чтения задаются inspect_options.maxTurns/maxCharacters; fullAudit включает проверку полной истории в пределах этих лимитов. Неполное или усечённое чтение возвращает pending_history и не разрешает продвигать указатель. При переписанной/исчезнувшей границе полный аудит с complete_history: true может вернуть needs_history_review. Прежде чем сохранять новую границу, агент показывает изменения и обновлённую сводку человеку; history_reviewed_by_user: true допустим только после его явного одобрения. Этот путь не заменяет чтение и не нужен для обычного прироста или перехода текущего шага inProgress → completed; изменение ранее завершённой истории требует проверки.

Снимок для агента содержит только доступные видимые сообщения пользователя и итоговые ответы. Скрытые рассуждения, промежуточный вывод инструментов и полная переписка в общую базу не публикуются. Агент формирует проверяемую сводку: цель, выполненное, решения, основания и уверенность, ограничения, незавершённые вопросы и следующий шаг. При ограниченном чтении он отмечает неполноту; механический фрагмент последнего ответа не считается полной сводкой задачи. Секреты из видимых сообщений также запрещено переносить в открытый handoff.

Проверка создаёт локальный снимок с непрозрачным ID. Он фиксирует источник, границу и исходную принятую ревизию задачи. Сохранение сводки не вправе незаметно заменить эту базу более новой. При расхождении требуется прежний процесс review/выбора. Успех подтверждается чтением сохранённой ревизии. Новые сообщения после снимка остаются для следующей проверки; сохранение не означает, что чат перестал меняться.

## Неизменившиеся данные

Прежний отпечаток чата не создаёт новую запись и не требует повторной сводки. Дополнительно хранилище сравнивает нормализованные данные существующей задачи и проверенные связанные артефакты. При их равенстве возвращается прежняя ревизия со статусом unchanged; файлы ревизии не перезаписываются. Проверки expected_revision, полноты доставки и нерешённых ветвей выполняются до пропуска: одинаковые данные не позволяют обойти конфликт.

Команда «Закончи работу» по умолчанию охватывает все доступные чаты Codex; «Закончи работу только этот чат» ограничивает процедуру. Для каждого чата независимы статус сохранения сессии и готовность задачи. Idle, архивирование или конец ответа не доказывают completed. Конфликт одного чата не запрещает сохранить независимые изменившиеся чаты, если их базы проверены.

## Безопасность и хранение

Пути проверяются на выходы за границы, промежуточные symlink/junction и неоднозначные назначения. Восстановление производится в новый каталог. Это уменьшает риск ошибок перенаправления, но не является транзакцией против активной замены каталогов другим процессом.

Контрольные суммы устанавливают целостность, а не автора. Доверие к содержимому общей папки остаётся отдельной границей. Присутствие пакета не означает разрешения исполнить его код. Распределённые блокировки и цифровая подпись не реализованы.

Профиль Codex экспортирует консервативный набор настроек. Полные URL, env, заголовки и непрозрачные args заменяются ссылками; абсолютные пути становятся локальными привязками. Перенос статических секретов — отдельный зашифрованный vault. OAuth-кеши и системные хранилища учётных данных не клонируются.

Синхронизацию файлов выполняет сторонний клиент. Программа знает только полученные локально версии. Startup проверяет исторические объекты по хешам, что увеличивает стоимость чтения большой истории. Очистка старых объектов в этой версии отсутствует.
