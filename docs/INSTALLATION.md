# Установка и подключение

Рекомендуемый готовый комплект — `Agent-Workspace-Setup.zip`. После полной распаковки пользователь видит описание RTF, файл настройки агента и файл установки MCP. Файлы по очереди прикладываются в Codex с прямым поручением выполнить соответствующий шаг. Внутреннюю распаковку и настройку путей выполняет агент.

## Разделение компонентов

- Codex устанавливается пользователем отдельно.
- «Настройка агента» добавляет только управляемый блок в активный пользовательский AGENTS.override.md/AGENTS.md с резервной копией и сохранением остальных правил.
- MCP — локальная программа, которую клиент запускает по stdio. Node.js уже находится в готовом Windows x64 пакете.
- Общая `AI-Workspace` — отдельная существующая синхронизируемая база с workspace.json. Установочная папка её не заменяет.

## Первый запуск

Агент проверяет SHA-256 готового ZIP и список файлов, распаковывает пакет в новый локальный каталог, сверяет его манифест и размещает программу локально. Если корректное подключение уже существует, оно используется без повторного выбора папки.

Для первого подключения установленный FolderPicker.exe показывает стандартное окно. Пользователь выбирает существующую базу. Агент проверяет workspace.json до вызова `attach`; пустая папка не создаёт новую базу. Отмена прекращает зависимые шаги.

В config.toml добавляется только одно подключение с реальными абсолютными путями данного ПК:

```toml
[mcp_servers.agent-workspace]
command = "ABSOLUTE_APP_DIR/runtime/node.exe"
args = ["ABSOLUTE_APP_DIR/app.mjs", "serve", "--local", "ABSOLUTE_LOCAL_STATE"]
```

Значения ABSOLUTE_APP_DIR и ABSOLUTE_LOCAL_STATE необходимо заменить реальными путями: это не автоматически раскрываемые переменные Codex. Остальные настройки должны сохраниться. Предварительно сохраняются исходные байты, при записи проверяется отсутствие конкурентного изменения.

До проверки чтения чатов настройте локальный читатель по следующему разделу. После установки проверяются initialize → notifications/initialized → tools/list → workspace_startup. В 0.3.1 ожидаются 12 инструментов, включая workspace_scan_chats и workspace_save_chat. Проверка конфигурации через `codex mcp get` сама по себе не проверяет запуск сервера. После обоих шагов перезапустите Codex и проверьте новые инструменты в чате.

## Доступ к чатам и обновление с 0.2.2

Для обзора локальной истории нужен установленный Codex с поддерживаемым App Server. Агент определяет его действительный исполняемый файл на этом ПК и проверяет операции чтения; путь другого ПК не переносится. Не требуется копировать авторизацию в Agent Workspace или запускать агентские шаги в соседних чатах. Недоступность источника сообщается отдельно: наличие MCP не доказывает доступ ко всем чатам.

Перед первым workspace_scan_chats выполните готовый CLI прямыми аргументами:

```text
APP_DIR/runtime/node.exe APP_DIR/app.mjs configure-chat-reader --codex ABSOLUTE_INSTALLED_CODEX_EXE --home ACTUAL_CODEX_HOME --local LOCAL_STATE
```

APP_DIR, ABSOLUTE_INSTALLED_CODEX_EXE, ACTUAL_CODEX_HOME и LOCAL_STATE обозначают реальные абсолютные пути этого ПК. `--home` необязателен; укажите его только для действительного каталога Codex. Конфигурация записывается только в `LOCAL_STATE/codex-reader.json` и не синхронизируется. Читатель запускает локальный App Server для разрешённых операций чтения; модель не вызывается, переписки и авторизация не изменяются. При недостающем пути используется ограниченное локальное обнаружение, описанное ниже; выдуманный или чужой путь подставлять нельзя.

В 0.3.1 указывайте стабильный системный путь запуска установленного Codex, а не каталог отдельного обновления. Он может проходить через launcher/junction приложения: только для выбранного executable программа получает физический путь через realpath и проверяет его перед каждым открытием. В локальной конфигурации остаётся стабильный путь запуска, поэтому замена цели при обновлении Codex не требует ручной перепривязки. Недоступная или некорректная цель остаётся ошибкой, а не поводом запускать случайный файл. Проверки запрета symlink/junction в storage, общей базе и готовых пакетах не ослабляются.

Сначала используется уже настроенный корректный путь Codex. Только при его отсутствии или отсутствии файла выполняется ограниченный поиск: абсолютные каталоги PATH и известные каталоги установки текущего пользователя (включая Programs/OpenAI/Codex/bin и packages/standalone/current/bin действительного CODEX_HOME). Кандидаты объединяются по физическому файлу. Единственный найденный вариант можно использовать; CODEX_PATH_REQUIRED означает, что нужно выбрать папку установки/исполняемый файл, а CODEX_PATH_AMBIGUOUS — что нужно выбрать из нескольких установок. Версию автоматически не выбирают, диски целиком не сканируют, авторизацию не ищут.

На другом ПК или после переноса папок пути определяются заново: codex-reader.json и device.json остаются локальными и между ПК не копируются. Общая папка подключается через attach с проверкой workspace_id; пользовательские абсолютные пути не становятся общими настройками.

Перед сканированием получите известные текущие статусы чатов из приложения и передайте `active_session_ids`, а для текущего чата — `current_session_id`. Статус из отдельного процесса App Server не является достаточным доказательством отсутствия работы в основном приложении.

Первый вызов workspace_scan_chats фиксирует перечень на время прохода. Продолжайте страницы с возвращённым `run_id` и `offset`, равным `next_offset`, пока next_offset не станет null. Не начинайте новый проход вместо каждой следующей страницы. Новые чаты и сообщения, появившиеся после снимка, относятся к следующему запуску; их не нужно будить сообщениями.

Проверяйте покрытие каждого изменившегося чата. `pending_history` и `partial` требуют дополнительного чтения до сохранения указателя. Для него можно повторить нужную страницу с увеличенными `inspect_options.maxTurns`/`maxCharacters` либо `fullAudit: true`; полная проверка тоже ограничена заданными лимитами. Если покрытие осталось неполным, не продвигайте границу и не объявляйте чат сохранённым целиком.

При `anchor_missing` или `anchor_changed` нужен полный аудит и сравнение переписанной истории. Если он прочитан полностью (`complete_history: true`), сканирование может вернуть `needs_history_review`. Покажите человеку найденные изменения и обновлённую сводку. Только после его явного одобрения вызовите workspace_save_chat с `history_reviewed_by_user: true`. Этот флаг не является общим разрешением на пропуск проверки и не применяется вместо чтения усечённой истории; обычный новый прирост и переход текущего шага inProgress → completed такого согласования не требуют. Изменение ранее завершённой истории по-прежнему требует проверки.

Обновление размещается в новом локальном каталоге версии. Перед узкой заменой command/args сохраняется конфигурация; остальные MCP и значения остаются прежними. Старый пакет и резервная копия сохраняются для возврата. Общая база schema_version 1 подключается через attach, без повторной инициализации. Версия 0.2.2 не умеет выполнять новый обход чатов: после обновления нужны соответствующий runtime и управляемый блок инструкций 0.3.1.

Первое сохранение закрепляет устойчивые связи чатов с задачами и границы обработки. В дальнейшем неизменившиеся чаты пропускаются. Чаты с текущей работой или неполным чтением отражаются в результате; нельзя считать все чаты сохранёнными только по успешному старту сервера. Истории других ПК и недоступные удалённые чаты не подменяются локальными данными.

## Ручное подключение готового runtime

`Setup.cmd` позволяет выбрать папку и подключить/создать базу, но не регистрирует MCP в Codex. Для переноса уже существующей базы предпочтительна команда `attach --root PATH --local LOCAL_STATE`, поскольку она не создаёт новую базу при ошибочном выборе пустой папки.

Команды выполняет агент по инструкциям; отдельной фоновой службы для них нет. «Начни работу» продолжает текущую задачу. «Закончи работу» проверяет все доступные чаты Codex и сохраняет сводки изменившихся. «Закончи работу только этот чат» ограничивает сохранение текущим чатом. Полные правила находятся в шаблонах packaging/simple. Само прикрепление файла не заменяет поручение пользователя выполнить установку.

Официальные источники: https://learn.chatgpt.com/docs/extend/mcp?surface=cli и https://learn.chatgpt.com/docs/agent-configuration/agents-md.
